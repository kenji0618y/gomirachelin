# 記事執筆ルール（文体・SUSURUルール・スコアリング）

**この文書のルールは、サイトの根幹的な合意事項です。勝手に変更しないでください。**
特に「SUSURUルール」は **訴訟リスクを避けるための法的安全ルール** であり、必ず守ってください。

---

## 1. 文体（「コスパ正直レビュー版・しきじ版」に固定）

| ルール | 内容 |
|---|---|
| 語調 | **です・ます調**。温かく、正直なトーン |
| 姿勢 | 価値があるものは素直に褒める。欠点は思いやりを持って正直に書く |
| 締め | 愛情を込めて（例：「私は、愛せる側です」） |
| 欠点の見出し | **「△」を使う。「×」は絶対に使わない** |
| 長さ | **約200〜300字**（厳守。450〜600字は長すぎる） |

### 廃止された文体

**旧・毒舌／ぶつ切りの「Doragon sauna」スタイルは二度と使いません。**
過去にこのスタイルで書いていた時期がありますが、しきじ版に移行してから完全に廃止されました。
過去記事を参考にするときは、必ず「しきじ版」の記事を参照してください。

## 2. ★SUSURUルール（法的安全性のための必須ルール）★

**GOMIRACHELINの全記事に適用される、絶対ルールです。**

### ① 「事実」と「評価」を必ず分離する

記述の順番：

```
訪問日時 → 混雑状況 → 観察した事実（温度計の数値、席数など） → 個人的な印象
```

これらを明確に区別して書きます。

### ② 断定的なネガティブ表現は禁止

| ❌ NG | ✅ OK |
|---|---|
| 衛生管理ができていない | 私が訪問した時は床に水たまりが目立った |
| 店員の態度が最悪 | 声かけが少なく感じた |
| ぼったくり | （料金と体験の対比を数字で示す） |
| 潰れる／詐欺／危険 | （使わない） |

### ③ △（欠点）ポイントの記述は必ず主観・体感形にする

- 「私が訪問した時は〜と感じた」
- 「〜が気になった」
- 「〜かもしれない」

### ④ 検証不能な事実は書かない

自分が直接観察・体験していないことは記述しません。
**伝聞（スタッフから聞いた話など）を事実として書くのは特に危険です。**

### ⑤ 深夜割引 ≠ 深夜割増

割引は記録上「なし」扱いとします。

**サイト側の表示は一貫しています**（トップページ・ランキングページの説明文・
10項目別ランキングの見出し・全個別記事のスコアカード、すべて同じ）。
つまり **サイトの表示が現行の正** である可能性が高く、GAS内の列コメントが
古いまま残っている（軸の定義が途中で改定された）と推測されます。

**⚠️ ただし、もし本当にスプレッドシートの中身が列コメント通りなら、
公開済みの全記事で⑤⑦⑧のスコアが誤ったラベルで表示されていることになります。**
影響が大きいので、**推測で修正せず、必ずKenjiさんに確認してください。**

確認すべきこと：
1. スプレッドシートv12の12〜21列目（s1〜s10）のヘッダー行に、実際に何と書かれているか
2. サイトの表示（休憩／ロウリュ／スパ内施設／スパ外施設／清潔さ）が意図通りか

> **⑩について**：「立地」ではありません。立地の要素はタイパの計算に吸収されています。
> これは両方の資料で一致しています。

### 計算式

```
パフォーマンス = ①+②+③+④+⑤+⑥+⑦+⑧+⑨+⑩   （0〜100）

円/時間 = 平日料金(J列) ÷ 滞在時間(K列)

コスパ点 = 円/h を換算表で変換（安いほど高得点）
コスパ   = パフォーマンス × コスパ点 ÷ 10

タイパ点 = 主要駅からの移動時間(分)を換算表で変換（近いほど高得点）
タイパ   = パフォーマンス × タイパ点 ÷ 10
```

### コスパ点の換算表

| 円/時間 | 点数 |
|---|---|
| ≤60 | 10 |
| 61〜100 | 9 |
| 101〜150 | 8 |
| 151〜200 | 7 |
| 201〜300 | 6 |
| 301〜400 | 5 |
| 401〜500 | 4 |
| 501〜600 | 3 |
| 601〜700 | 2 |
| 701〜 | 1 |

## 4. J/K列（平日料金・滞在時間）の判定ルール

スコア計算の分母になる重要なデータです。施設タイプごとに決め方が違います。

| 施設タイプ | J（料金）の決め方 | K（滞在時間）の決め方 |
|---|---|---|
| 時間制限あり | 該当プランの料金 | 制限時間を使用 |
| フリータイム（無制限） | フリータイム料金 | 営業時間全体 |
| 24h営業＋深夜割増あり | 基本料金 | 割増なしで居られる時間帯（例：8:00〜翌2:00＝18h） |
| 複数プランあり | サウナを含むプラン | 同上 |

## 6. 表示・カラーシステム

### ★禁止事項★

- **白背景に金／黄色テキスト：厳禁**（可読性がゼロになる）
- 金色（`#d4a017`）は **ダーク背景上** の見出しと数字にのみ使用する
- 明るい黄色 `#f4c430`、オレンジ `#e8a948`、白 `#e8e2d4` を本文テキストに使うことは禁止

### 記事本文の色（CSSで上書きしない）

| 要素 | 色 |
|---|---|
| 本文・見出し・結論 | `#d4a017`（ゴールド） |
| スコアバー（グラデーション） | `#d4a017` / `#b8922a` / `#8a6d0f` / `#5a4a1c` |
| メリット（○） | `#d4a017` |
| 欠点（△） | `#a08030` |
| コスパ関連 | `#d4a017`（ゴールド） |
| タイパ関連 | `#4caf50`（グリーン） |

> **WordPress時代の注意（静的化後は解消済み）**：
> `.entry-content p { color: ... }` というCSSが記事側の色指定を上書きし、
> 黒背景に黒文字で読めなくなる事故が起きていました。
> 静的サイトではこの問題は発生していませんが、`css/site.css` に本文色の
> 全称セレクタを足すときは同じ事故を起こさないよう注意してください。

## 7. 校閲（プルーフリーディング）機能

GAS側に実装されている、記事の事実確認機能です（静的サイトには存在しません）。

### フロー

1. ユーザーが記事を編集中に「校閲」ボタンを押す
2. スプレッドシート列AE（公式URL）から施設の公式サイトURLを取得
3. 公式サイトのHTMLをフェッチしてテキスト化
4. 記事テキスト＋公式テキストをClaude APIに送信
5. **SUSURUルール＋事実確認**に基づく修正版が返される
6. 結果が別エリアに表示され、「本文に適用」ボタンで反映

### フォールバック

以下の場合は「SUSURU単独チェック」（公式サイトとの突合なし）になります。

- 公式URLが空
- Instagram URL
- HTML取得失敗

### 実装ファイル

`gomira_kouetsu_button.gs`（GAS側の独立モジュール）

| 関数 | 役割 |
|---|---|
| `_kouetsuHtmlToText()` | HTMLからテキスト抽出 |
| `_kouetsuFetchOfficial()` | 公式サイトのHTML取得 |
| `_kouetsuReasonMsg()` | 修正理由メッセージ生成 |
| `_kouetsuBuildPrompt()` | Claude API用プロンプト構築 |
| `reviewArticleAI(text, url)` | メイン関数 |
| `injectReviewUI_(html)` | 校閲ボタンUIを既存HTML_PAGEに注入 |
