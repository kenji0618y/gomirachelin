# GitHub Pagesのパス問題と方式選択（Codexへの相談用）

最終更新：2026-09-06 Codex追記

## 解決済み（2026-09-06）

Codexが方式Aを採用し、リポジトリ名を `kenji0618y.github.io` へ変更した。`https://kenji0618y.github.io/` でトップ、CSS、主要メニュー、静的地図が正常に表示されることを確認済み。DNS、ConoHa、メール、GAS、Sheetsは変更していない。以下は判断時の記録として残す。

## 結論を先に

**GitHub Pagesの無料URL（`kenji0618y.github.io/gomirachelin/`）では、このサイトは正しく表示できません。** サイトを「ドメインの一番上」に置く必要があります。方式が2つあり、**Kenjiさんが決めかねているのでCodexの意見を求めています。**

## 現在の状況

- リポジトリは公開（Public）に変更済み。GitHub Pagesも有効化済み（`main` / `/(root)`）。
- しかし発行されたURLは `https://kenji0618y.github.io/gomirachelin/` というフォルダ形式。

## 問題の詳細

このサイトは全ページで**ルート絶対パス**（`/`で始まるパス）を使っている。

- 実測：`href="/..."` と `src="/..."` の形の参照が**合計1,434か所**
- 内訳の例：`/`（124）、`/ランキング/`（121）、`/why/`（121）、`/sauna-university/`（120）、`/お問い合わせ/`（119）、`/css/`（60）、`/10項目別ランキング/`（60）ほか

フォルダ形式のURLで公開すると、`/css/site.css` は `kenji0618y.github.io/css/site.css`（＝`gomirachelin`フォルダの外）を探しに行き**404**になる。結果、**CSSが読み込まれずデザインが崩れ、メニューと内部リンクが全滅する。**

本番の `sauna-cospa.com` ではサイトがドメインの一番上にあるため、この書き方で正しく動いている。**サイト側の作りの問題ではなく、GitHubの無料URLがフォルダ形式であることが原因。**

## 検討した方式

### 方式A：リポジトリ名を `kenji0618y.github.io` に変更する

- GitHubの仕様上、`<ユーザー名>.github.io` という**正確な名前**のリポジトリだけが `https://kenji0618y.github.io/` （ルート）で公開される。
- 長所：DNSを一切触らない。すぐ確認できる。無料。
- 短所：
  - URLに `sauna-cospa` の文字が入らない。
  - GitHubアカウントで1つだけの「ユーザーサイト枠」を消費する。
  - リポジトリ名が変わるため、他のAI・ローカルクローン・ブックマークのURLに影響が出る（GitHubはリダイレクトしてくれるが、設定の見直しは必要）。

### 方式B：テスト用サブドメイン `test.sauna-cospa.com` を割り当てる（Claudeの推奨）

- ConoHaのDNSに**CNAMEレコードを1行追加**（`test` → `kenji0618y.github.io`）し、GitHubのPages設定の「Custom domain」に `test.sauna-cospa.com` を入れる。リポジトリに `CNAME` ファイルも追加する。
- 長所：
  - サブドメインなのでサイトがルートに来る。**1,434か所のパスがそのまま動く。**
  - **本番の `sauna-cospa.com` とメール設定には一切触らない**（新しい1行を足すだけ）。本番はConoHaで動き続ける。
  - 本番切替の**予行演習**になる。最終切替時に同じ手順を安心して実行できる。
  - 無料。
- 短所：
  - DNS操作が1回必要。反映に数分〜数時間かかる場合がある。
  - `CNAME` ファイルは最終切替時に `sauna-cospa.com` へ書き換えが必要（1行）。

### 却下した案

- **リポジトリ名を `sauna-cospa.com` にする**：Kenjiさんからの提案。リポジトリ名にドットは使えるが、URLは `kenji0618y.github.io/sauna-cospa.com/` となり**フォルダ形式のまま**なので問題は解決しない。
- **1,434か所を相対パスへ書き換える**：変更量が多くリスクが高い。将来独自ドメインへ移した後は不要な複雑さが残る。
- **`<base>`タグを使う**：`/`で始まるパスには効かないため解決しない。

## Codexへ相談したいこと

1. 方式Aと方式Bのどちらを推奨するか。他に見落としている選択肢はあるか。
2. 方式Bの場合、ConoHaのDNS画面での**CNAMEレコード追加の具体的な操作手順**（Codexはブラウザを操作できるため、実際の画面を見て案内・実施できる）。
3. 方式Bで、本番の A レコード・MX・TXT に**絶対に触れない**ための注意点。

## 補足：ロードマップとの関係

- `docs/GitHub移行ロードマップ.md` の「中止条件」に「テスト公開に重大な404や表示崩れがある場合は、独自ドメインを切り替えない」とある。今回の問題は**方式の問題**であり、サイト自体の不具合ではない点に注意。
- `CNAME` について同ロードマップの優先Bに「DNSのバックアップと復旧手順が完成するまで追加しない」とある。DNSの現在値は `docs/dns-mail-公開記録.md` に記録済み。**方式Bはサブドメインの追加のみで既存レコードを変更しない**ため、この条件に抵触しないとClaudeは考えるが、Codexの確認を求める。
