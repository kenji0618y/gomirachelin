# ConoHaバックアップ手順

最終更新：2026-09-05

対象：`sauna-cospa.com`

保存先：`gomirachelin-work/backups/conoha/2026-09-05/`

## 基本方針

- 確認とダウンロードだけを行う。
- ConoHa上の削除、移動、上書き、復元、DNS変更、解約は行わない。
- WordPressのバックアップは秘密情報を含む可能性があるためGitHubへ入れない。
- GitHubには、秘密情報を除いた構成・確認結果・不足一覧だけを記録する。

## 再ログイン後の順番

1. 「サーバー管理 → 自動バックアップ」で、Web・Mail・DBの各バックアップが「リストア可」になっている日付を確認する。
2. 「サイト管理 → データベース」でWordPressが使うデータベース名を確認する。
3. phpMyAdminから対象データベースをSQL形式で `database/` へエクスポートする。
4. ファイルマネージャーまたはFTP/SFTPで `public_html/sauna-cospa.com` を `web/` へ保存する。少なくとも `wp-content/uploads` と `wp-config.php` の取得を確認する。
5. DNSのA・AAAA・CNAME・MX・TXT・NS、メールアドレス・転送設定、ドメイン契約・更新情報を `dns-mail/` へ記録する。
6. ファイル数、容量、SQLファイルの有無を確認し、`docs/STATE.md` と全体ロードマップを更新する。

## 注意点

- ConoHa WINGの自動バックアップは過去14日分。WebとMailのリストアで作られたファイルは24時間後に削除されるため、移行用の恒久保存は手元に別途取得する。
- 「リストア」は確認のために押さない。必要になった場合だけ、影響を確認して別作業として行う。
- 大きなファイルを扱う場合は、ファイルマネージャーよりFTP/SFTPを優先する。
- `wp-config.php`、SQL、メール設定、DNSの認証用TXTは公開しない。

## 完了条件

- `web/` に公開フォルダーのバックアップがある。
- `database/` に開けるSQLバックアップがある。
- `dns-mail/` に切替前のDNS・メール・契約情報がある。
- GitHubに不足している画像・設定ファイル・URLの一覧がある。
