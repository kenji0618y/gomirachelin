# GASとGitHubの役割分担

**最終方針：2026-09-04 決定**

> ⚠️ **この文書は一度「GAS廃止計画」として書かれましたが、方針が変わりました。**
> 検討の経緯は末尾の「経緯」に残してあります。

---

## 結論：GASは残す。変えるのは「投稿先」だけ

| システム | どうする | 理由 |
|---|---|---|
| **スマホアプリ（GASの編集アプリ）** | ✅ **残す** | Kenjiさんの主力ツール。移動中・訪問後の入力に不可欠 |
| **スプレッドシート GOMIRACHELIN_v12** | ✅ **残す** | 採点データの正本 |
| **GAS（記事生成・校閲）** | ✅ **残す** | アプリと一体。動いているものを壊さない |
| **記事の投稿先** | 🔄 WordPress → **GitHub** | ここだけ変える |
| **WordPress** | ❌ 廃止 | 管理の手間とサーバー代の原因 |
| **ConoHa** | ❌ 廃止 | サーバー代が浮く |
| **GitHub Pages** | ✅ 公開場所 | pushすれば自動公開 |

### 流れの比較

```
【今】
  スマホアプリ → スプレッドシート更新 → 記事生成 → WordPressに投稿
                                                    → ConoHaが配信

【これから】
  スマホアプリ → スプレッドシート更新 → 記事生成 → GitHubに投稿
                                                    → GitHub Pagesが自動配信
```

**変わるのは矢印の最後だけです。** アプリの操作手順は一切変わりません。

## #2：投稿先の差し替え

### 用意したもの

`gas/github_post.gs`（このリポジトリに収録済み）

| 関数 | 役割 |
|---|---|
| `testGitHubConnection()` | 接続確認。読み取りだけで何も変更しない |
| `testPostArticle()` | テスト記事を1本投稿してみる |
| `postArticleToGitHub(o)` | **記事投稿の本体。** `postArticleToCospa()` の置き換え |
| `updateFacilitiesOnGitHub(list)` | ランキングの `FACILITIES` を差し替える（#8） |
| `ghPutFiles(files, msg)` | 複数ファイルを1回のコミットで書き込む（内部用） |

導入手順は **`gas/README.md`** を参照してください。

### 認証の仕組みは今と同じ

| | WordPress（今） | GitHub（これから） |
|---|---|---|
| 認証情報 | `WP_APP_PASS` | `GITHUB_TOKEN` |
| 置き場所 | GASのスクリプトプロパティ | **同じ場所** |
| コードに書くか | 書かない | **書かない** |

Kenjiさんが新しく覚えることはありません。

### 投稿時に更新されるファイル

`postArticleToGitHub()` は次の3つを **1回のコミットで** 更新します。

1. `{施設名}/index.html` … 記事ページ本体
2. `data/urls.json` … ページ一覧に登録
3. `sitemap.xml` … 検索エンジン向けの一覧に登録

1つずつ書くと途中で失敗したとき中途半端になるため、
**全部成功するか、何も変わらないか**のどちらかになるようにしています。

### まだ自動化されていないもの

投稿しても、次の2ページは自動更新されません。

- `reviews/index.html`（レビュー一覧）
- `サイトマップ/index.html`（サイトマップ）

どちらもリポジトリ内のPythonスクリプトで作り直せます。

```bash
python3 scripts/gen_reviews.py
python3 scripts/gen_sitemapp.py
```

**当面はAIに「反映して」と頼めば済みます。** 将来GAS側からも作れるようにするかは未定です。

## #6：マップ機能の扱い（保留）

GASの `?page=map` にLeafletのマップ機能があります（13種フィルター、都道府県タイル＋ピン）。

**GASを残すので、この機能は失われません。** ただし現在、サイトのメニューからは
リンクされていないため、訪問者は使えていない可能性が高いです。

判断が必要になったとき：

| 案 | 内容 |
|---|---|
| A | GASのマップにサイトからリンクを張る（アクセス設定が「自分のみ」だと訪問者は見られない点に注意） |
| B | 静的ページとして作り直す（LeafletはCDNから読めるので静的サイトでも動く） |
| C | このまま保留 |

> **注意**：GASのアクセス設定を「自分のみ」に変更済み（2026-09-04）のため、
> **今のままサイトからリンクしても、訪問者はマップを開けません。**
> 公開したい場合は案Bが現実的です。

## 経緯（なぜ一度「GAS廃止」に傾いたか）

2026-09-04、利用者から次の要望がありました。

> 「gasもこれからgithubだけにしたい。スプレッドシートはそのまま」

これを受けてGAS廃止計画を作成し、さらに「スプレッドシートも含めてGitHub + AIだけ」に
できる案を提案しました。しかし利用者から次の判断がありました。

> 「スマホで記事を投稿のアプリはすごく便利なので、アプリでスプレッドシートを更新して
> 記事を投稿する流れは変えたくない。デメリットが大きい」

**この判断は妥当です。** GAS廃止で得られるのは「構成がすっきりする」ことだけで、
失うのは「移動中にスマホで完結する入力・投稿の快適さ」でした。
Kenjiさんが実際に毎回使う道具の使い勝手のほうが、構成の美しさより優先されます。

一方で、当初の目的だった「WordPressの管理の手間」と「サーバー代」は、
**投稿先を差し替えるだけで解消できます。** そのため現在の方針に落ち着きました。

### この経緯から学べること（今後のAIへ）

**「一本化」「シンプル化」それ自体は目的ではありません。**
Kenjiさんが実際に困っていること（WordPressの管理・サーバー代・手動アップロード）を
解消することが目的です。動いていて本人が気に入っている道具を、
構成の美しさのために取り上げる提案はしないでください。
