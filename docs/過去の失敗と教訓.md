# 過去の失敗と教訓

**このプロジェクトで実際に起きた失敗の記録です。同じ失敗を繰り返さないために読んでください。**

> 出典：2026-09-02のClaude引継ぎ資料＋2026-09-04のClaude Codeセッションでの実体験。

---

## ★最大の教訓：当てずっぽうで直さない★

### 何が起きたか

記事の表示がおかしくなったとき、原因を特定せずに「たぶんこれだろう」で修正し、
**Kenjiさんに25回以上も再デプロイ・再投稿を頼んだ**ことがあります。
Kenjiさんは非常に不満を持ちました。

### なぜ起きたか

**真犯人はGAS側ではなくWordPressの追加CSSでした。**
`.entry-content p { color:#1a1a1a !important; }` が記事側の色指定を上書きし、
**黒背景に黒文字**で読めなくなっていたのです。
GAS側をいくら直しても直るはずがありませんでした。

### 教訓

1. **表示がおかしいときは、まずCSSを疑う。GASやコードを疑うのは後。**
2. **必ず「実際に公開されているHTMLまたはCSL」を見てから対処する。**
3. **診断してから直す。** 「CSSが原因か、生成コードが原因か」を切り分ける
4. Kenjiさんに作業を頼むのは「原因が特定できてから」

> 静的サイト化した今、この特定の問題は解消しています。
> しかし **「推測で直して他人に検証を頼む」というパターン自体が最大の失敗要因**です。

## 表示・CSS関連

### `.entry-content p` の色上書き問題

WordPressのCocoonテーマは `.entry-content p` に文字色を設定します。
記事本文はGASが黒背景＋ゴールド文字で組んでいたため、これが上書きされると読めなくなりました。

**教訓：全称セレクタで本文色を指定するCSSを足すときは、
黒背景ボックスの中身まで巻き添えにしないか必ず確認する。**

### 白背景に金色テキストは厳禁

可読性がゼロになります。金色（`#d4a017`）は**ダーク背景上でのみ**使用してください。
→ 詳細は `docs/記事執筆ルール.md` の「表示・カラーシステム」

## データ操作の失敗

### 施設名の不一致で書き込みが失敗した

GASでスプレッドシートに一括書き込みするとき、施設名のMAPを作りました。
しかし **スプレッドシート上の実際の表記と違っていて、静かに失敗**しました。

| スプレッドシート上 | 使ったキー | 結果 |
|---|---|---|
| `TOTONOI` | `小倉サウナTOTONOI` | ❌ 不一致 |
| `神戸サウナ` | `神戸サウナ&スパ` | ❌ 不一致 |

**この2件のJ/K値（TOTONOI: J=1300/K=12、神戸サウナ: J=3100/K=18）は
未書き込みのまま残っている可能性があります。**

### 教訓

1. **MAPを作る前に、必ずスプレッドシートの実際のセル値を読み取って確認する**
2. 正規化関数 `norm()` を使う（NFKC正規化 + 小文字化 + `&`→`and` + 記号・空白除去）
3. **書き込み後に「一致件数・未一致件数」を必ずログ出力する。**
   静かに失敗させない

### Drive MCPの読み取り切り詰め

Drive MCP経由でスプレッドシートを読むと、**約54行目あたりで切り詰められる**ことがあります。
実際は200行超あるのに「これで全部だ」と誤認する危険があります。

**教訓：`getLastRow()` などで必ず総行数を確認してから作業する。**

## 2026-09-04のセッションで実際に踏んだ落とし穴

### 1. Pythonの `%` 書式が、%エンコードURLと衝突する

```python
entry = '<loc>https://example.com/%E3%82%B5/</loc><lastmod>%s</lastmod>' % today
# → TypeError: must be real number, not str
```

URL内の `%E3` `%82` をPythonが書式指定子だと勘違いします。

**対策：`%` 演算子を使わず、文字列連結か `.format()` か f-string を使う。**

同じ理由で、`.format()` を使うテンプレート内の `{` `}` は `{{` `}}` にエスケープが必要です
（`scripts/gen_*.py` の中のJavaScriptやCSSが該当）。

### 2. 一括置換が「2系統のhref」を取りこぼす

サイト内のリンクには2つの書き方が混在しています。

| 書き方 | 例 | ファイル数 |
|---|---|---|
| 日本語そのまま | `href="/ランキング/"` | 62 |
| %エンコード | `href="/%E3%83%A9%E3%83%B3%E3%82%AD%E3%83%B3%E3%82%B0/"` | 2 |

メニューに「サイトマップ」を一括追加したとき、**%エンコード側のファイルだけ
フッターが更新されませんでした。** 気づいたのは後から検証スクリプトを回したときです。

**対策：一括置換の後は必ずリンク検証スクリプトを回す。
「更新できなかったファイル」のリストも出力する。**

### 3. 自動生成ページを手で直すと、次の実行で元に戻る

`reviews/index.html` を手で直しても、`scripts/gen_reviews.py` が上書きします。

**対策：直すのは「スクリプトの中のテンプレート」。** その後スクリプトを実行する。

### 4. ヘッドレスChromeのスクリーンショットが切れる

`--window-size` を指定しても画像の下半分が欠ける現象。

**対策：`--force-device-scale-factor=1` と
`--run-all-compositor-stages-before-draw` を必ず付ける。**

### 5. WordPress由来のタグ閉じ忘れを「バグ」と誤認する

HTMLの構文チェックをかけると**44ファイル**で「未閉じタグ」が出ます。

**これはWordPressの出力に元からあるもので、直してはいけません。**
ブラウザは問題なく表示します。直そうとすると差分が巨大になり、
本文を壊すリスクの方が大きいです。

### 6. ドキュメントを1つだけ更新して満足する

`docs/STATE.md` は毎回更新していたのに、`README.md` の更新を忘れ、
**「変更は grok bot 1 に頼んでください」という古い記述が残ったまま**になっていました。
Kenjiさんから指摘を受けて発覚しました。

**対策：作業のたびに STATE.md だけでなく、README.md と関連手順書も見直す。**

## インフラ・アカウント関連の失敗

### ★WordPress.comでアカウントBANされた★

旧ブログ（`saunagomirachelin.wordpress.com`）で**自動一括投稿**を行ったところ、
WordPress.comが検知して**アカウントを停止**しました。

その後、新ブログ経由で最終的に `sauna-cospa.com`（WordPress.org + ConoHa WING）へ移行。
**記事投稿は手動コピペ方式に確定**し、自動投稿でのBAN再発を回避しています。

**教訓：外部サービスの自動化は、規約違反でアカウントを失うリスクがある。
特に「大量・高速な自動投稿」は危険。**

### ConoHa WINGのWAFがブロックする

- Code Snippets保存時はWAFを一時的に無効化する必要がある
- REST API経由の投稿で `SyntaxError: Unexpected token '<'` が返る場合、
  HTMLがJSON代わりに返っている＝サーバー側でブロックされている

### GASが動かないときのチェック順

| 症状 | 原因 |
|---|---|
| 401エラー | APIキーが間違い／失効 |
| 400エラー | **API残高切れ**（過去にUSD 3.86で切れた） |
| 529エラー | API一時混雑。再試行する |
| 反応しない | `ANTHROPIC_KEY` のスペル（大文字・アンダースコア）／「保存」ボタンを押したか |

## ツール・実装の制約

| 制約 | 内容 |
|---|---|
| ファイル生成ツール | 約400行を超えると出力が途中で切れる。200〜400行単位に分割して `cat` で結合 |
| GASの実行時間 | 6分でタイムアウト。長時間処理は冪等にして複数回実行する設計にする |
| `.gs` の構文チェック | 拡張子を `.js` にコピーして `node --check` で検証できる |
| `.gs` 内の文字列JS | 文字列リテラルとして埋め込まれたブラウザ側JSは、別途抽出して単体検証が必要 |
| WordPress固定ページ | `/wp-json/wp/v2/pages` は `/posts` と**別**。一括置換で漏れた前例あり |
| カスタマイザー操作 | `document.body.innerHTML = ''` を**絶対に実行しない**（保存ボタンが消える） |
