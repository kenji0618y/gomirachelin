WordPressの元ページにGASのiframeが埋め込まれていたため、書き出したHTMLにURLが含まれ、
そのままコミットされていました。**現在のファイルからは消えていますが、Gitの履歴には残ります。**

### なぜこれが問題なのか

GASのWebアプリURLは、「アクセスできるユーザー：全員」でデプロイされている場合、
**URLを知っているだけで誰でもそのWebアプリを開けます。**

しかもGASは「実行するユーザー：自分（Kenjiさん）」で動くため、
編集アプリ画面から `saveFacility()` が呼ばれると、
**第三者がKenjiさんの権限でスプレッドシートを書き換えられる可能性があります。**

### ✅ 対処済み（2026-09-04）：GASのアクセスを「自分のみ」に変更

**Kenjiさんが対応済みです。**

GASのデプロイ設定で「アクセスできるユーザー」を **「自分のみ」** に変更しました。
これにより、履歴に残ったURLを第三者が開いても **アクセス拒否される**ため、無害化されています。

> Git履歴を書き換える（`git filter-repo` 等）必要はありません。
> 履歴の書き換えは操作が複雑で失敗しやすく、初心者には推奨しません。

**この設定を戻さないでください。** 「全員」に戻すと、履歴のURLが再び有効になります。

**副作用として知っておくこと：**

- GASのWebアプリは **Googleにログインした状態でないと開けません**（Kenjiさん本人のみ）
- そのため **GASのマップページ（`?page=map`）にサイトからリンクしても、訪問者は見られません**
  → マップを公開したい場合は、静的ページとして作り直す必要があります
  （→ `docs/GASとGitHubの役割分担.md`）

## 1. リポジトリ側の準備【完了済み】

すでに以下のファイルを追加済みです。追加作業は不要です。

| ファイル | 役割 |
|---|---|
| `.nojekyll` | GitHub Pagesが標準で動かす「Jekyll」という仕組みを止める。中身は空でよい |
| `CNAME` | 独自ドメインを使う設定。中身は `sauna-cospa.com` の1行だけ |
| `404.html` | 存在しないURLを開いたときに出る案内ページ |

**なぜ `.nojekyll` が必要か**：Jekyllはアンダースコア始まりのフォルダを無視するなど、
勝手な処理をします。このサイトは素のHTMLなので、その処理は不要かつ有害になりえます。

**`CNAME` の注意**：GitHubの設定画面でカスタムドメインを設定すると、GitHubが自動的に
`CNAME` ファイルを書き換えることがあります。手元のファイルと食い違ったら、GitHub側の値を正とします。

## 3. GitHub Pages を有効にする

**GitHubの画面での操作です。AIエージェントからは操作できないので、利用者が行ってください。**

1. https://github.com/kenji0618y/gomirachelin を開く
2. 上部の「**Settings**」（歯車アイコン）をクリック
3. 左メニューの「**Pages**」をクリック
4. 「Build and deployment」の「Source」で「**Deploy from a branch**」を選ぶ
5. 「Branch」で「**main**」、フォルダは「**/ (root)**」を選び、「**Save**」
6. 1〜2分待つと、ページ上部に公開URLが表示される
   （最初は `https://kenji0618y.github.io/gomirachelin/` のような仮のURL）

### この時点での確認

仮のURLを開いて、サイトが表示されるか確認します。

> **注意**：この仮URLでは、CSSや画像が読み込まれず **レイアウトが崩れて見えます。**
> このサイトのリンクはすべて `/css/site.css` のように「/」始まりで書かれているため、
> `github.io/gomirachelin/` のようなサブフォルダ形式では正しく解決されないためです。
> **これは不具合ではありません。** 次の手順で独自ドメインを設定すると正しく表示されます。

## 4. DNS を GitHub Pages に向ける【ここで本番が切り替わる】

**ドメインを管理している会社の管理画面での操作です。**
まず「`sauna-cospa.com` のDNSをどこで管理しているか」を確認してください
（ConoHaのドメイン機能か、お名前.comなど別の会社か）。

### 4-1. GitHub側でカスタムドメインを設定

1. Settings →「Pages」→「Custom domain」に `sauna-cospa.com` と入力し「Save」
2. GitHubがDNSの確認を始める（この時点ではまだエラー表示でよい）

### 4-2. DNSレコードを設定

ドメイン管理画面で、以下のレコードを設定します。

**ルートドメイン（`sauna-cospa.com`）に Aレコード4つ：**

```
種別: A   ホスト名: @（または空欄）   値: 185.199.108.153
種別: A   ホスト名: @（または空欄）   値: 185.199.109.153
種別: A   ホスト名: @（または空欄）   値: 185.199.110.153
種別: A   ホスト名: @（または空欄）   値: 185.199.111.153
```

**IPv6にも対応させる場合（任意）AAAAレコード4つ：**

```
種別: AAAA   ホスト名: @   値: 2606:50c0:8000::153
種別: AAAA   ホスト名: @   値: 2606:50c0:8001::153
種別: AAAA   ホスト名: @   値: 2606:50c0:8002::153
種別: AAAA   ホスト名: @   値: 2606:50c0:8003::153
```

**www付きでもアクセスできるようにする場合：**

```
種別: CNAME   ホスト名: www   値: kenji0618y.github.io
```

> ⚠️ **上記のIPアドレスは変更される可能性があります。** 作業する時点で
> GitHubの公式ドキュメント（「Managing a custom domain for your GitHub Pages site」）を
> 開いて、最新の値と一致するか必ず確認してください。

**既存のレコードの扱い**：ConoHaのサーバーを指している既存のAレコードは、
上記に **置き換え** ます（削除して新規作成、または値を書き換え）。
念のため、変更前の設定内容をスクリーンショットで残しておくと安心です。

### 4-3. 反映を待つ

DNSの変更が世界中に行き渡るまで、数分〜最大48時間かかります（多くは1時間以内）。
GitHubのPages設定画面で緑のチェックが付けば成功です。

反映状況はこのコマンドで確認できます（手元のパソコンのターミナルで実行）：

```bash
dig sauna-cospa.com +short
# → 185.199.108.153 などが返ってくれば切り替わっている
```

## 5. HTTPS を有効にする

DNSの確認が通ると、GitHubが自動でSSL証明書を発行します（数分〜1時間程度）。

1. Settings →「Pages」→「**Enforce HTTPS**」のチェックボックスをオンにする
2. グレーアウトしていて押せない場合は、証明書の発行待ち。しばらく待ってから再度開く

これで `http://` でアクセスしても自動的に `https://` に転送されるようになります。

- [ ] 日本語URLの記事（例：`https://sauna-cospa.com/らかんの湯/`）が開く ← **特に重要**

> **必ず複数の日本語URL記事を開いて確認してください。**
> もし開けない場合は、フォルダ名をローマ字に変える大工事が必要になるため、

**6番の確認がすべて通ってから、最後に行います。**

1. 数日〜1週間ほど、GitHub Pagesで問題なく動くことを様子見する
2. WordPressのデータをバックアップする（記事・画像・データベース）

## 移行後の運用イメージ

移行が完了すると、更新の流れはこうなります。

```
【今まで】
  HTMLを直す → ConoHaにFTPで手動アップロード → 反映

【これから】
  HTMLを直す → GitHubの main ブランチにpush → 1〜2分で自動的に反映
```

利用者はGitコマンドを覚える必要はありません。AIエージェントに変更を頼めば、
そのままpushまで行われ、サイトに反映されます。

## トラブルシューティング

| 症状 | 考えられる原因と対処 |
|---|---|
| デザインが崩れる（文字だけ表示） | `css/site.css` が読めていない。仮URL（github.io/リポジトリ名/）で見ていないか確認。独自ドメイン設定後に再確認 |
| 404 Not Found ばかり出る | Pages の Source が `main` / `/ (root)` になっているか確認 |
| 日本語URLの記事が開かない | フォルダ名の文字コードの問題。作業を止めて相談する |
| 「Custom domain is not properly configured」 | DNSがまだ反映されていない。`dig sauna-cospa.com +short` で確認して待つ |
| Enforce HTTPS が押せない | 証明書の発行待ち。1時間ほど待って再確認 |
| 更新したのに変わらない | ①pushできているか ②GitHubの「Actions」タブでデプロイが成功しているか ③ブラウザのキャッシュを消す（Ctrl+Shift+R） |
